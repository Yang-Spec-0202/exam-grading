# Implementation Plan：自动作业批改系统（exam-grading）

> 版本：v0.2 · 2026-11-05 · 状态：执行中（M0–M8 已完成，M9 部分完成（UI 人工验收待办），M10 进行中；逐项证据见 `tasks/todo.md` 状态总览与 `docs/dev/acceptance.md`）
> 规范基线：`SPEC.md` v0.2.1、12 份 `SPEC-<module-id>.md`、`CONFIG.md`、`AGENTS.md`
> 原则：先检索后编码（`AGENTS.md`）；小步垂直切片；每 2–3 个任务一个验证检查点；任何失败显式可见。

## 1. 概述

用 Rust + Slint 做一个单机离线桌面应用：教师录入参考答案与评分规则（可手写→模型整理→确认，或套用全国卷模板），批量导入学生作业（文件名即学生），本地 OCR/LaTeX 识别、对齐、两层判分（标准/快速双模式），复核低置信度与主观题，导出成绩与统计。

首版只做数学；core 学科无关；无账号；云端仅兜底且逐任务授权；原图永久保留；完整日志与文档。

## 2. 架构决策（摘自规范，不再重复论证）

1. **依赖单向**：`domain` ← `platform` ← 各功能模块 ← `app`（组合根）。跨模块只经 `domain` 类型与模块公开 trait。
2. **判分两层**：L1 有序路由表（纯函数，仅题型未知时分类澄清）→ L2 比较器链 → 未决升级 L2 决策模型 → 规则聚合；缺答案禁止模型造答案。
3. **双模式**：标准/快速两套阈值；快速模式按比例 0.20、低置信度权重 0.70 加权抽检；抽检不通过弹窗重跑（默认单题）。
4. **规则必须确认**：模型只产草稿；确认后版本递增；草稿不参与判分。
5. **身份只看文件名**：未命中即未决人工；不做 OCR 兜底（可配置但默认关）；导入时提醒规范命名。
6. **单机单写者**：SQLite WAL + 单写连接；内容寻址资产库只读、无删除；任务队列持久化、断点续跑、幂等。
7. **推理隔离**：所有模型调用经 `inference`；本地 sidecar 默认离线；云端默认关、任务级授权；输出严格 Schema 校验。
8. **可复现**：每条判分记录带模式、规则/答案键/识别/模型/提示词/配置版本与证据链。
9. **零示例代码**：本计划与规范均不含代码片段；实现以规范与官方文档为准。

## 5. 并行与串行

**必须串行**：M0 → M1（类型与 schema 是所有模块的前提）；`domain` 类型变更；数据库迁移；判分路由表语义。
**可并行**（M1 完成后）：`capture` 与 `inference` 与 `subject-math` 三条线；`rubric` 的本地校验与模板数据；测试夹具准备（脱敏样卷）可与实现并行。
**需先定契约**：`grade` 依赖 `rubric`/`subject-math`/`inference` 的接口——先落各模块根导出的 trait 与 `domain` 类型，再并行实现。
**UI 最后**：`app` 依赖 `review`/`report`/`platform`/`inference` 的视图模型与接口，等 M7 完成后接入。

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 本机无 Rust 工具链 | 阻塞一切 | T01 第一优先；记录安装版本到 research 记录 |
| Slint API/IME/大图性能不确定 | UI 返工 | T02 用官方文档逐项验证；先做最小窗口 + 图片组件的技术验证 |
| 16GB 内存跑 0.9B OCR + 4B 判定 | 延迟/显存不足 | 先用 fixture 打通全链路；模型侧先做单页基准；必要时降上下文/量化/串行 |
| OCR 对手写公式识别率低 | 判分质量差 | 置信度门禁 + 人工修文本；夹具先用印刷体，手写单独评估 |
| PDF 渲染库打包/许可 | 阻断 PDF 输入 | T02 验证候选；失败则 v1 仅图片+扫描 |
| CAS（sympy）sidecar 依赖 Python 3.12 | 启动复杂 | 独立进程 + 超时降级；不可用即「无法判定」，不影响主链路 |
| 全国卷模板数据缺失/过期 | 规则不可用 | 以最新公开试卷快照为准；模板数据单独版本化；缺失时禁止套用并提示 |
| 准确率目标（S2/S3）依赖真实标注集 | 验收失败 | 先建立 100–200 题脱敏金标集；每次改比较器/提示词回归 |
| 真实作业样本与隐私 | 无法做端到端 | 公开试卷 + 自造学生答案；脱敏流程与夹具规范先行 |
| 范围膨胀（微积分/多学科/学生端） | 延期 | 按 `SPEC.md` v1 排除项拒绝；扩展走变更审批 |

## 8. 验收数据准备（与实现并行）

1. 脱敏金标集：20 题×5 学生（含选择/填空/计算/证明/「略」/仅规则/多解/跨页/低质量照片/手写）。
2. 每例含：原图、期望识别（可选手工标注）、答案键、评分规则、期望判分与证据说明。
3. 夹具目录结构与 `egctl replay` 对齐；所有姓名/学号替换为合成值。
4. 性能基线脚本：单页识别、单题判定、20 题×40 份批量、导出 1000 份。

## 9. 开放问题（开始实现前需确认）

1. **样例数据**：是否有可用的历史作业照片/试卷（脱敏后）？没有则用公开试卷 + 自造答案，准确率验收口径需相应放宽。
2. **全国卷模板数据来源**：由谁提供最新公开试卷的结构与分值（模板数据文件），还是由实现阶段按公开卷整理一版快照？
3. **本地模型来源与硬件**：OCR/判定模型由用户先下载到 `models/`，还是实现阶段提供下载脚本并验证？是否就是 M4/16GB？
4. **云端兜底**：是否需要预置某个 OpenAI 兼容端点，还是纯配置项留空？
5. **发布平台**：GitHub Pages 的仓库地址/组织是否已定（影响 mdBook 配置与链接）。
6. **试用节奏**：是否希望 M2（判分核心，无 UI）先交付一版 CLI 试用，再继续 UI？
