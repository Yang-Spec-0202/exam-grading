# ADR-0008：规范文件不含示例代码

> 状态：已接受 · 2026-11-02 · 决策者：项目（单机匿名教师）· 相关规范：`SPEC.md` §1.12/§9/§10 Never、`CAPABILITY-MAP.md` §7、`AGENTS.md`
> 说明：本 ADR 解释「为什么规范里连代码块都不写」；门禁执行见 `scripts/docs-check.sh`。

## 1. 背景

- 规范会被当作实现阶段的上下文交给模型；示例代码（尤其是 JSON/Rust/Slint 片段）极易被当作「已确认的接口」直接照抄，而示例往往滞后于规范正文与依赖实测。
- 用户明确要求所有规范文件不得包含示例代码（含代码块、JSON、Rust/Slint 语法示例），并已写入 `SPEC.md`。
- 项目采用「检索优先」纪律（`AGENTS.md`）：版本与 API 事实应来自官方文档与实测，而不是规范里的示例。
- 需要可执行的机械门禁，避免「下不为例」。

## 2. 决策

- **零围栏**：`SPEC.md`、`SPEC-*.md`、`CAPABILITY-MAP.md`、`CONFIG.md` 内不得出现三反引号代码围栏；类型名、字段名、快捷键、命令可用行内代码。
- **契约用表格**：类型、字段、不变量、接口职责、枚举取值一律用表格与文字描述；需要表达「形状」时描述字段语义，不给可粘贴片段。
- **门禁强制**：`scripts/docs-check.sh` 扫描上述文件，命中围栏即失败；`scripts/ci.sh` 与 CI 均调用。
- **文档与规范分工**：用户/开发者文档可以有少量行内命令，但不写大段可复制代码；API 细节留给官方文档与研究记录（`docs/dev/research/`）。
- **实现期不靠规范抄代码**：研究记录负责「官方文档 + 实测版本 + 结论」，规范只负责「必须/禁止/验收」。

## 3. 后果

- 正面：规范不会把过时 API 固化成「事实」；模型实现时被迫查官方文档与实测；规范更短、更稳定；评审关注行为而非语法。
- 负面：描述复杂接口时更啰嗦；开发初期需要更多研究记录；文档读者不能直接从规范复制签名。
- 后续动作：新增规范文件默认纳入检查列表；若确需展示数据形状，用字段表 + 语义说明；ADR 与开发文档不受「零围栏」限制，但仍避免大段代码。

## 4. 替代方案

| 方案 | 优点 | 缺点/风险 | 结论 |
|---|---|---|---|
| A：允许示例代码（仅标注「示意」） | 阅读直观 | 极易被照抄；示例滞后即误导；用户明确禁止 | 放弃 |
| B：只禁止 JSON/配置示例，允许 Rust 签名 | 保留接口可读性 | 签名同样会过时；门禁无法机械判定 | 放弃 |
| C：零代码围栏 + 行内类型名（采用） | 可机械门禁；不提供可复制片段 | 复杂契约描述更长 | **采用** |
