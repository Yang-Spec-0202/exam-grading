# ADR-0007：CAS 扩展（sympy sidecar）与不可用即降级

> 状态：已接受 · 2026-11-02 · 决策者：项目（单机匿名教师）· 相关规范：`SPEC.md` §4（符号计算）、`SPEC-subject-math.md`（CAS 适配层）、`CONFIG.md` §8
> 说明：本 ADR 解释「为什么用外部 CAS、为什么它必须可降级」；接口与预算以规范与研究记录为准。

## 1. 背景

- 数学必须覆盖根式、三角、向量、矩阵、区间、集合（用户确认）；只靠字符串归一与数值比较无法判定「三角恒等式等价」「矩阵相等」「集合相等」。
- 纯 Rust 生态缺少成熟、许可友好的通用 CAS；自研等价判定在三角/矩阵上容易做出「看起来对但漏判」的规则，风险高于收益。
- 目标机 16GB、默认离线；CAS 若作为常驻服务会挤占模型内存，若每次冷启动又太慢。
- 规范要求「无法判定 ≠ 答错」：CAS 不可用或超时必须显式降级为「无法判定」，转模型或人工，不能阻塞整批判分。

## 2. 决策

- **外部 CAS 适配层**：`subject-math` 通过独立子进程调用 sympy（Python 3.12，由 uv 托管，用户无需手装），通过 JSON-lines 协议收发；只把「两表达式差是否为 0 / 矩阵行列式 / 解集比较」等有限问题交给 CAS。
- **启动与超时预算**：sidecar 启动超时 10 秒；单次化简超时 3 秒（`cas.timeout_s`，1–10 可调）；超时或不可用立即返回「无法判定」。
- **降级顺序**：比较器链中 CAS 只作为其中一环；CAS 不可用 → `Inconclusive` → 升级 L2 模型 → 仍无法判定则人工；绝不因 CAS 故障把学生判错。
- **可配置开关**：`cas.enabled` 默认开、`cas.cache` 默认开、解释器路径自动探测；关闭或探测失败时该比较器直接不可用，判定链继续。
- **离线与许可**：sympy 为 BSD-3，随 `uv` 环境本地安装，不联网；Python 运行时不进仓库、不打包分发（A7 不分发）。
- **范围边界**：微积分、复数、几何证明不在本轮必须项；超出即转模型/人工（用户已接受）；若试用中人工过多，再扩展 CAS 能力。

## 3. 后果

- 正面：三角/矩阵/集合等价判定可靠；CAS 故障不致错判；按需启动与缓存控制内存；许可风险低。
- 负面：引入 Python 3.12 运行时依赖（经 uv，不要求用户手装，但首次准备需要下载与校验）；单次 3 秒超时对批量判分是可见成本；CAS 结果仍可能「化简不出」。
- 后续动作：研究记录 `cas.md` 记录了协议草案与实测预算；若 CAS 超时率居高，优先调整分块与缓存而不是放宽超时；扩展能力需先改规范并补研究记录。

## 4. 替代方案

| 方案 | 优点 | 缺点/风险 | 结论 |
|---|---|---|---|
| A：纯 Rust 自研 CAS/等价规则 | 无外部进程、启动快 | 覆盖不足；三角/矩阵误判风险高；维护成本大 | 放弃 |
| B：Symbolica（Rust 商业 CAS） | 性能与集成好 | 商业许可，与 GPL-3.0-only 分发口径冲突，需采购 | 放弃（许可风险） |
| C：不做 CAS，全部交给模型/人工 | 零依赖 | 三角/矩阵等大量题转人工，快速模式失效 | 放弃 |
| D：sympy sidecar + 超时降级（采用） | 能力覆盖与许可平衡 | Python 依赖与超时成本 | **采用** |
