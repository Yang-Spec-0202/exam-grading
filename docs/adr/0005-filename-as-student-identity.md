# ADR-0005：文件名即学生身份

> 状态：已接受 · 2026-11-02 · 决策者：项目（单机匿名教师）· 相关规范：`SPEC.md` A2/§13.1、`SPEC-align.md` §3.2、`SPEC-capture.md` §3.2/§3.4、`SPEC-report.md` §3.2、`CONFIG.md` §3
> 说明：本 ADR 解释「为什么身份只认文件名」；归一化细节与未决项处理以规范为准。

## 1. 背景

- 单机匿名教师、无登录、无条码印刷条件（v1 无解码器，`identity.barcode` 默认关）；名单由教师导入（学号、姓名）。
- 手写姓名/学号 OCR 在真实作业上错误率高，且错配（把 A 的成绩记到 B）比漏配更难发现、后果更严重。
- 用户明确答复：身份只看文件名，「不管」不规范文件名；只在选择文件时提示规范命名。
- 输出侧同样要求以文件名称为准（试卷名/学生名/模式命名导出文件），形成「输入—输出」一致的命名约定。

## 2. 决策

- **唯一身份来源**：`Submission.source_stem`（去扩展名文件名）归一后与名单学号/姓名精确匹配；精确且名单唯一 = 置信度 1.000，直接确认；`identity.source` 在 v1 只启用「文件名」。
- **归一化规则**：去首尾空白、全半角统一、连续空白折叠、去可解析的页码后缀（如 `_p1`、`-第2页`）；归一后仍不命中即未命中。
- **未命中即人工**：默认交未决项，教师在名单中检索并选定；候选按名单学号/姓名排序，不按相似度自动排序；不存在「最像就选它」的自动兜底。
- **OCR/条码默认关闭**：`identity.ocr_fallback`、`identity.barcode` 默认关；开启需 Ask first，且与文件名冲突时一律未决（不得静默择优）。
- **不纠正文件**：应用不重命名用户文件；只在选择文件时提示「建议按 学生名/学号 命名」（`import.remind_naming` 默认开）。
- **名单外也不自动判分**：即使 `identity.unmatched_behavior=自动归入名单外`，该提交也只留诊断、不自动出分，待补名单或标记无效（`SubmissionExclusion`）。
- **导出命名同源**：整卷用「试卷名_模式_时间戳」，学生成绩单用「学生名_试卷名_模式_时间戳」，脱敏另加后缀；命名规则与清洗细节写入用户文档。

## 3. 后果

- 正面：零 OCR 幻觉错配；规则简单可测（分支覆盖 ≥90%）；教师只需一次规范命名；输入输出命名一致，便于归档。
- 负面：对教师命名纪律强依赖；相机自动命名（`IMG_0032`）批次会整批进人工，需批量改名（应用外完成）；重名同姓且文件名无学号时必然未决。
- 后续动作：导入页需清楚展示「文件名 → 学生」预览与未匹配清单；批量改名工具是否内置列为开放问题（`SPEC-align.md` §10）；若未来印刷条码，再开启 `identity.barcode` 并补历史回填方案。

## 4. 替代方案

| 方案 | 优点 | 缺点/风险 | 结论 |
|---|---|---|---|
| A：OCR 学号/姓名优先 | 无需规范命名 | 手写识别错误 → 错配进成绩；纠错成本高；用户明确否决 | 放弃（仅保留默认关闭的兜底开关） |
| B：条形码/二维码 | 最可靠 | v1 无解码器与印刷条件；改造成本高 | 推迟（保留开关与 `BlockKind.Barcode` 变体） |
| C：文件名 + OCR 融合打分 | 召回高 | 冲突时仍需人工；易被误用为「自动择优」 | 放弃（冲突一律未决） |
| D：文件名唯一来源 + 未命中人工（采用） | 简单、零错配、可测 | 依赖命名规范 | **采用** |
