# ADR-0001：采用 ADR 记录架构决策

> 状态：已接受 · 2026-11-02 · 决策者：项目（教师侧单机应用）

## 1. 背景

- 规范（`SPEC.md`、`SPEC-<id>.md`）只写「必须/禁止/验收」，不解释取舍过程。
- 项目存在多个关键决策（两层判分、双模式、规则结构化、CAS 选型、文件名身份、按任务鉴权、规范无代码），后续实现与评审需要可追溯的决策上下文。
- `SPEC.md` §9 要求 ADR 覆盖上述决策，并与规范变更同一次提交。

## 2. 选项

| 选项 | 优点 | 缺点/风险 | 结论 |
|---|---|---|---|
| A：只在规范里写结论 | 文件少 | 无法追溯「为什么不选另一种」，评审与交接成本高 | 放弃 |
| B：独立 ADR 目录 + 编号 + 模板 | 决策可追溯；与规范分工清晰；便于增量评审 | 需要维护索引与模板 | 采用 |
| C：写进提交说明 | 零额外文件 | 不可检索、易丢 | 放弃 |

## 3. 结论

- 采用 B：`docs/adr/`，编号四位递增，模板 `_template.md`，索引维护在 `docs/adr/README.md`。
- ADR 只记录决策与影响，不复制规范条文；规范变更与 ADR 同一次提交。

## 4. 影响

- 正面：决策背景可追溯；评审可引用 ADR 编号。
- 负面：每新增关键决策需多写一份短文档。
- 后续动作：按 `docs/adr/README.md` 索引补齐 SPEC.md §9 要求的 7 项决策。
